ไฟล์นี้สรุปสเปกที่ตกลงกันแล้วและงานที่ทำไปแล้ว ให้ session ถัดไปทำงานต่อได้ทันที

## สถาปัตยกรรม
- Cloudflare Worker ชื่อ `students-report` (repo `SATTASAI/students-report`) มี static assets อยู่ใน `public/`
- ใช้ D1 ร่วมกับ banpadeng-school-db: binding `DB` → `banpadeng_school_db`, database_id `870fa9ec-122f-4161-a1ca-cc9979dcfa30` (ต้องประกาศไว้ใน wrangler.jsonc)
- ใช้บัญชีจากตาราง `users` เดียวกัน และต้องตั้ง secret `JWT_SECRET` ให้เป็นค่าเดียวกับ school-db
- ตารางใหม่ทั้งหมดขึ้นต้นด้วย `gr_` (`src/lib/schema.js`) ระบบสร้างให้เองเมื่อ Worker ทำงานครั้งแรก
- รายชื่อนักเรียนต่อห้อง/ปีดึงจาก `student_enrollments` ของภาคเรียนล่าสุดในปีนั้น ส่วนปีการศึกษาและภาคเรียนดึงจาก `academic_years` / `academic_terms`
- ข้อมูลจริง ณ 7 ต.ค. 2569: นักเรียน 813 คน, ปี 2569 (id 1), ภาค 1 (id 1) และภาค 2 (id 2, เริ่ม 1 พ.ย.) ภาค 2 ยังไม่มีข้อมูลการลงทะเบียน ห้องมีตั้งแต่ อ.1–ป.6 ระดับละ 2–4 ห้อง
- ในเครื่องทดสอบใช้ wrangler ไม่ได้ (npm ถูกบล็อก) ให้ทดสอบด้วย node:sqlite ทำ shim แทน D1 แบบเดียวกับ tests ของ school-db

- `batchAll` ส่งเป็น batch เดียว (= transaction เดียว) เมื่อไม่เกิน 500 คำสั่ง — เดิมตัดทุก 90 คำสั่งทำให้ล้มกลางทางแล้วค้างครึ่งชุด; เกิน 500 (นำเข้าทั้งโรงเรียน) ยังแบ่งชุด
- บันทึกคะแนน: upsert รวม 20 แถว/คำสั่ง และลบคะแนนรวม 45 แถว/คำสั่ง (`(item_id, student_id) IN (VALUES …)`) วางทั้งตารางหลายร้อยช่องได้ในครั้งเดียว
- `guardedBatch` + ตาราง `gr_guard` (CHECK ชื่อ `gr_guard_tripped`): บันทึกคะแนน/ผล (`saveCourseData`) สำเร็จเฉพาะเมื่อสถานะล็อกยังเท่ากับตอนตรวจสิทธิ์ ไม่งั้นยกเลิกทั้งชุดตอบ 409
- `gr_courses.data_rev` เพิ่มทุกครั้งที่บันทึกคะแนน/ผล · ส่งผล: ตอบ `data_rev` มากับรายการตรวจ, ยืนยันส่ง `expect_rev` · ล็อกด้วย `WHERE locked = 0 AND data_rev = ?` → ถ้ามีคนแก้ระหว่างนั้นไม่ส่ง ให้ตรวจใหม่
- หน้ากรอกคะแนน: กดส่งผลแล้วรอการบันทึกที่ค้างให้เสร็จก่อน (ไม่เกิน ~15 วินาที), มีช่องไม่ถูกต้องส่งไม่ได้, ได้ 409 แล้วโหลดข้อมูลใหม่

## ตรวจระบบละเอียด (25 ต.ค. 2569) — ผู้ใช้ตัดสินใจแล้ว
- SAR: ผลการเรียน/คุณลักษณะ/กิจกรรม นับเฉพาะห้องนำร่อง (ถ้าตั้งไว้) · มาเรียน ≥80% นับเฉพาะห้องที่มีบันทึกการมาเรียนแล้ว (เดิมห้องที่ไม่ใช้ระบบถูกนับเป็นผ่าน/มาเรียน 100%) · รายงานสรุปผลสัมฤทธิ์แสดงเฉพาะห้องนำร่อง
- แก้การมาเรียน/ปฏิทินวันหยุดหลังรายวิชาส่งผล: ผลเปลี่ยนตาม สถานะไม่เปลี่ยน แต่บันทึกประวัติใน gr_course_edits ของรายวิชาที่ส่งแล้ว (`logLockedCourses`) — แทนการดึงวิชาที่อนุมัติแล้วกลับไปอนุมัติใหม่
- แก้กิจกรรมพัฒนาผู้เรียนหลังอนุมัติ → `reopenApprovedForRoom` เหมือนคุณลักษณะฯ
- สรุปสมรรถนะ = รวมคะแนน 0–15 (เหมือนอ่าน คิด เขียน)
- รับกลับเข้าเรียนในปีเดียวกัน: แท็บคะแนนยกมาแสดง/รับเฉพาะภาคที่นักเรียนยังไม่มีคะแนนในระบบ (ลบคะแนนยกมาเดิมได้เสมอ)
- ร้อยละมาเรียน (attendanceRates): นับวันเรียนตั้งแต่ต้นภาคแรกที่มีบันทึก gr_attendance ในปีนั้น (ห้องนำร่องภาค 2/2569 ภาค 1 อยู่ใน Q-Info จึงนับเฉพาะภาค 2)
- ยังไม่แก้ (เล็ก): แก้โครงสร้างไม่เพิ่ม data_rev, บันทึกขาดล่วงหน้าได้, ย้ายห้องกลางปีใช้ ร/มส/แก้ตัวของห้องปัจจุบัน, คะแนนแก้ตัวค้างหลังคะแนนเดิมผ่าน
